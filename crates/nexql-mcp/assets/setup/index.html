    Step 1 · Connection

    Which database should the assistant use?

    A profile is a saved connection: where the database is, who to log in as, and the rules for it. Pick one you saved before, or add a new one.

    A short label you'll use in commands and see in your app, like local or billing-prod.

    localhost for a database on this computer or in Docker, or a name like db.example.com.

    5432 unless it was changed. Docker uses the host side of -p.

    Password

    Checking where passwords can be stored…

    It goes straight to safe storage when you press Continue. It is never written to config.toml or to any app's config, and the assistant never sees it.

    A command that prints the password. nexql-mcp runs it each time it connects, so nothing is stored here. It takes priority over a stored password.

    Step 2 · Test

    Checking the connection

    nexql-mcp logs in the way your app will, runs SELECT version(), and checks whether the user is a superuser.

    Step 3 · Access & safety

    What may the assistant do?

    These rules are checked on every call. Start with read: you can raise it later for a single profile.

    Access mode

    This lets the assistant change your data. Destructive statements like DROP TABLE still need your confirmation in the chat, but a mistaken UPDATE doesn't. Use it on a development database, or connect as a role whose privileges you've limited.

    Tick the box to confirm, or choose Read.

    Personal data

    Turn this off only for a database full of fake or test data. Real people's details would be sent to your AI provider.

    Schemas, tables and limits optional

    The assistant sees only these. Leave empty for every schema the user can read.

    Hidden even when the user could read them.

    schema.table, with * to match many.

    schema.table.column, on top of the automatic rules.

    Most rows one query returns. Empty means 500.

    Postgres cancels a query that runs longer. Empty means 30 seconds.

    The default is used when an app starts nexql-mcp without --profile.

    Step 4 · Apps

    Which apps should use it?

    nexql-mcp is added to each app's MCP config as a server called nexql-mcp. Other servers in those files are left alone. The config holds the command and the profile name, never a password.

    How apps start nexql-mcp
