02 Connection setup

One connection string.
Or a profile you can trust.

Use a positional URL for a quick session. For teams and repeatable environments, keep named profiles in ~/.config/nexql-mcp/config.toml.

Fastest path

One-off connection

Nothing is written to disk. Great for a local database or a temporary investigation.

$ nexql-mcp postgres://dev@localhost:5432/appdb
Recommended for shared workflows

Profiles keep intent visible

default_profile = "local"

[profiles.local]
url = "postgres://dev@localhost:5432/appdb"
access_mode = "read"

[profiles.prod]
host = "prod.example.com"
dbname = "app"
user = "readonly_agent"
password_command = "op read op://vault/pg/password"
sslmode = "verify-full"
access_mode = "read"
schemas = ["public", "billing"]
deny_tables = ["auth.*"]
pii_columns = ["public.users.ssn", "public.users.email"]
max_rows = 200

◎ Never store plaintext secrets in config. Use password_command, the OS keyring, or DATABASE_URL. Set NEXQL_MCP_CONFIG to override the config path.

04 What it can do

Useful context, not
just a query pipe.

The active catalog groups schema discovery, query work, context, performance, write, admin, and connection setup into one MCP server.

01

Schema

Search objects, describe tables, find join paths, inspect DDL, compare schemas, and surface missing foreign keys.

search_schema · describe_object · get_join_path · schema_diff
02

Query

Run safe selects, explain plans, export results, and analyze or tune expensive queries.

run_select · explain_query · export_query · auto_tune_query
03

Performance

Inspect table stats, index usage, locks, slow queries, health, bloat, and missing index opportunities.

db_health_check · slow_queries · suggest_indexes
04

Context

Keep the agent oriented across connections, server settings, dashboard signals, and index state.

switch_connection · server_settings · db_dashboard
05

Write + Admin

Opt into mutations only when you mean to. Transactions, dry runs, and explicit access modes keep the sharp edges visible.

execute_sql · apply_ddl · run_maintenance
06

Connection

Set up, test, save, export, and import profiles without leaking secrets into project config.

setup_connection · test_profile · export_profile
⌁

Schema index is the moat. NexQL builds a local index with lexical search, inferred join graphs, value profiles, and optional embeddings — so the model can ground its next action in the database that actually exists.

05 Safety model

Start narrow.
Open up deliberately.

All tools are advertised to the MCP client, but access is enforced at call time. A write-capable model should never be an accidental default.

Access modeRead toolsWrite toolsAdmin tools
read defaultallowedrefusedrefused
writeallowedallowedrefused
adminallowedallowedallowed
01

Use schemas, deny_tables, pii_columns, and max_rows to scope a profile.

02

Write/admin startup refuses superuser connections unless --i-know-what-im-doing is explicit.

03

Use dry_run=true for transactional write and DDL tools before applying changes.

06 Optional transport

Stdio by default.
HTTP when you need it.

Local desktop clients usually want stdio. For a service or remote sidecar, enable the built-in HTTP transport and protect any non-loopback bind with a bearer token.

Streamable HTTP

Bind it deliberately

Default port is 8899. Non-loopback binds are refused without --http-token or NEXQL_MCP_HTTP_TOKEN.

Read transport notes ↗
$ NEXQL_MCP_HTTP_TOKEN=change-me \ nexql-mcp --http \ --bind 0.0.0.0 --http-port 8899
07 If something is off

Diagnose the path,
then the client.

01 The client says it cannot spawn the server

Run which nexql-mcp (or where nexql-mcp on Windows), then use nexql-mcp init <client> again. If you installed with npm, make sure the package's bin directory is on PATH.

02 The connection works, but the agent sees no useful schema

Run nexql-mcp postgres://… doctor, then build the index with nexql-mcp postgres://… index build. Check that the profile's schemas list includes the objects you want.

03 Linux reports a glibc error

Prebuilt GNU/Linux binaries require glibc 2.35+. Upgrade to a current release, build with cargo install nexql-mcp, or use the published Docker image.

04 I need guided setup

Run nexql-mcp tui. It can create and test profiles, merge client config, show a diff, and keep a timestamped backup before writing.
